# ARDEX PRO Admin Acceptance

The connected local build now has functional operating paths for attention items, job timelines, product replacement review, evidence comparison, invoice reconciliation, support resolution, shortage recovery, eligible re-offers, applicator profiles and proposed pilot settings. This describes local acceptance, not production deployment approval.

| Area | Functional path | Check |
| --- | --- | --- |
| Overview and review queue | Filter attention by owner and open the relevant work record | Guided browser rehearsal and scoped/all-record views |
| Jobs | Search/filter, exact job deep link, source-to-handover timeline and all-jobs return | Guided and retained end-to-end checks |
| Product correction | Requested SKU and size, reserved dealer pack, exact on-site scan, reasoned admin review | Domain and cross-port browser checks |
| Evidence | Frozen requirements beside captures, challenge and flood review, retained redo history | Existing stage/gate tests and browser journeys |
| Handover | Customer concern invalidates closing confirmation and pauses eligibility | New domain test; fresh permission required after resolution |
| Issued records | Evidence cannot be reassessed; separate reasoned withdrawal remains available | Domain integrity tests and existing void controls |
| Commercial values | Quote, declared invoice, reviewed invoice and direct receipt separately labelled | Guided browser rehearsal and domain validation |
| Dealers | Packing, shortages, replacement handoff, declared invoice and actual reconciled count | Guided browser rehearsal; readiness blocked during shortage |
| Applicators | Manage opens the profile; job/back navigation and certification persist | Applicator-profile browser checks |
| Catalog and accounts | Existing versioned configuration and account revocation remain restricted | Server permissions checks |
| Pilot | Proposed targets persist, invalid values reject, Admin cannot save | Pilot controls and permissions checks |
| Audit and recovery | Actions retain actor, reason and history; unavailable connection has a retry | Domain authority tests and operating interfaces |

Production-oriented corrections include immutable issued evidence, exact supplied-pack matching, reservation conflict checks, preserved rejected scans, support holds, cancellation release of reservations, amount consistency before receipt confirmation, differentiated configuration permissions and safe persistence of changed registry entries. Read-only state requests no longer hydrate the registry, and operational summaries exclude archives rather than transferring them on each refresh.

Remaining live-launch dependencies are deliberate boundaries: individual user/customer ownership, production identity and sessions, trusted signed packaging, real messaging and delivery receipts, secure media storage and retention, approved technical configuration, actual participants and coverage, warranty backing, payment-provider verification where adopted, backup/restore, monitoring, deployment security and an agreed measurement baseline. Shared local roles represent fictional participants. Routing and care scheduling are proposed configuration/preferences, not connected production services. See PRODUCTION-HANDOFF.md.

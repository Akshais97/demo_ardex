# ARDEX PRO Guided Presentation

Open http://127.0.0.1:5173 and select Presenter. The default experience is Ananya’s seven-chapter terrace journey. Choose Begin Ananya’s journey on an empty record, or Start a fresh journey to create a separate presentation session. Existing jobs and their history remain intact. Keep http://127.0.0.1:5175/admin.html available for the ARDEX operating view.

## Enquiry

The website enquiry already contains Ananya’s name, address, symptom and reference photos. Confirm service permission, hairline cracks, visit slot and address. The replies are persisted alongside the booking. Structural concerns stop booking and create a technical follow-up. Refusing permission stops service messages; the homeowner can explicitly resume them.

Say: “The conversation carries the enquiry forward. It does not make her start again.” Continue to Inspection after the visit is booked.

## Inspection

Accept the visit. Choose sample site location for a laptop presentation or live GPS where suitable. Load reference diagnosis photos, confirm the site condition and measurements, calculate eligible packages and send the quote. The reference terrace is 700 sq ft treated area. Show the actual measurement breakdown rather than implying a universal coverage rule.

Say: “The site condition determines the eligible system. The measurement determines the quantities.” Final diagnosis is a human responsibility; package selection and calculations use versioned rules. Continue to Decision.

## Decision

Ananya’s conversation contains the quote produced by this same job. Inspect the selected scope, materials, pack sizes, stages and labour. Approve Terrace Shield Plus for the reference sequence. The current illustrative quote is ₹66,940, comprising ₹50,140 materials and ₹16,800 labour. Selecting a different eligible option changes the frozen scope and subsequent kit; it is not merely a visual selection.

Say: “She approves a scope, not an unexplained number.” Continue to Supply after approval. A declined scope can be revised in the applicator view; an already approved scope cannot silently change.

## Supply

Send the approved kit list from Ravi’s phone. The tagged dealer receives it. Open Kit order, check each product line and mark readiness. A shortage can be flagged before readiness; Admin must record its resolution before the ready action succeeds. Optional dealer invoice entry records a declared amount and reference. Admin reconciliation remains separate.

After readiness, Ravi’s start permission form and Ananya’s conversation appear below. Enter the current START code from the conversation and confirm start. Continue to Exception.

Say: “The order comes from the accepted scope. Every substitution needs a decision.” Readiness is not delivery, invoicing or application proof.

## Exception

Click Scan the wrong product. A registered SKU outside the approved system is rejected and earns no quantity credit. Request the correct pack. In the dealer phone, select an unused matching registry pack and confirm replacement readiness. The supply command reserves it for this job. Ravi scans that exact supplied pack on site.

Use Inspect this record to open the admin panel on the same job. Sign in as Admin. In Product correction, document removal of the rejected product and inspection of the exact supplied, scanned replacement. Approve the documented correction. The original rejected scan remains. Merely scanning another eligible pack cannot resolve the requested replacement.

Say: “The mistake remains visible. The correction is visible too.” The presentation reviewer card also supports this action for Presenter; ordinary applicators and dealers cannot perform admin clearance. Continue to Completion only after blocking product exceptions resolve.

## Completion

Record the approved kit scans. Use Record next reference stage once for each required shot. This creates an explicitly generated reference record and advances the presentation clock to the configured curing boundary; it does not pretend physical work occurs in seconds. The camera and per-stage controls remain available in the applicator interface.

In Admin, compare recorded images with frozen requirements, visible stage challenges and the paired flood-test timestamps. Enter a decision reason and explicit challenge/flood assessment. Pass or fail each actual record. Failed work can be sent for redo, retaining superseded history and invalidating closing confirmation.

Run all six checks. After the first five requirements and start permission clear, request the homeowner closing code in Ravi’s phone. Open Homeowner confirmations and messages to read the current code. Confirm handover, rerun the six checks in Admin and issue the completion record. Issuance still fails if mandatory evidence is missing or a product exception is unresolved. A homeowner concern pauses handover; resolving it requires a fresh closing confirmation. Issued evidence cannot subsequently be reassessed or rewritten. Voiding the record is a separate audited action.

Say: “The handover has a record behind it.” Generated imagery is not field evidence, scanning is not measured application, and the local record is not an activated commercial warranty. Continue to Outcome after issuance.

## Outcome

The outcome summarises the same job: accepted scope, tagged dealer, credited scans, current stage records, corrected product issue and both homeowner confirmations. It separately labels quoted materials, declared/reconciled invoices and direct payment status.

Ananya can report paid or pending, rate the work and choose an annual-care preference. Ravi can confirm receipt after her paid acknowledgement. Two-party acknowledgement remains distinct from provider verification. Low ratings create an operations follow-up. Care preference is recorded but no scheduler or real WhatsApp delivery is connected. The enquiry website link supports voluntary referral.

Say: “The job ends. The record remains.” No profit, lifetime performance or incremental ARDEX sales claim follows automatically from this record.

## Admin operating view

Overview and Review queue show owner-filtered attention items: acceptance, reassignment, dealer readiness/shortages, product corrections, pending/failed evidence, handover, support, invoices and recipient acknowledgements. Every item opens its record. Use Record scope to choose all work or the current customer journey.

Job detail links the enquiry, scope, applicator, dealer, decisions and evidence. Applicator Manage opens the profile and its work history. The dealer view reports actual recorded invoice counts. Catalog and Accounts retain server-enforced restrictions. Pilot displays proposed scope, observed local story counts, targets and launch dependencies. Admin is operational; Super Admin can also save proposed pilot/configuration settings. No setting approves the real field pilot.

AI assists with conversational understanding and explanation in the intended product. The current copy is scripted. Approved rules calculate quantities and enforce checks. Qualified people diagnose, inspect images and resolve technical decisions.

## Verification and limitations

`npm run build` checks TypeScript and the production bundle. `npm test` includes consent, structural stops, replacement reservation/matching, support holds, invoice separation, issuance integrity and immutable issued evidence. `node scripts/check-guided-presentation.cjs` rehearses all seven chapters through the browser and checks admin navigation, reload persistence, mobile layout and public verification. `node scripts/check-end-to-end.cjs` checks the retained terrace and bathroom execution flows. `node scripts/check-permissions.cjs` checks role escalation, redacted OTPs and cross-job reuse.

This is a connected local prototype with production-oriented workflow controls, not a deployed production platform. The field pilot still requires individual identity and ownership, trusted product authentication, approved technical configuration, real messaging, secure durable media, warranty policy, operations/security acceptance and an agreed measurement baseline. See PRODUCTION-HANDOFF.md and the proposed pilot foundation.
